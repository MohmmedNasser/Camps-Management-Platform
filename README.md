# منصة إدارة مخيمات النازحين

منصة ويب عربية (RTL) لتسجيل النازحين والأسر في المخيمات، ومتابعة توزيع المساعدات والمستندات والمراسلات بين النازحين وإدارة المخيم. صُمّمت للجوال أولاً، وتعمل على واجهة خفيفة بلا إطار عمل وبلا خطوة بناء، فوق خلفية حقيقية على **Supabase** (مصادقة، وقاعدة بيانات PostgreSQL محمية بسياسات RLS، ودوال Edge) مع تخزين المستندات على **Cloudinary**.

## المزايا

| المجال | ما توفره المنصة |
|---|---|
| **النازحون** | قائمة مع بحث وفلاتر متقدمة مجمّعة (المخيم، الجنس، الحالة، نوع الخيمة، الفئة العمرية، الأيتام، الأمراض المزمنة، الحمل والرضاعة، نوع المساعدة، الجهة المانحة)، وملف تفصيلي من سبعة تبويبات، وإضافة وتعديل. |
| **الأسر** | تسجيل الأسرة ورب الأسرة وجميع أفرادها في نموذج واحد، ورقم مرجعي فريد يُولَّد تلقائياً (`FAM-000001`)، وفلاتر حسب خصائص الأفراد، وصفحة «أسرتي» للنازح. |
| **تفعيل حساب الأسرة** | رابط تفعيل لمرة واحدة صالح 7 أيام يولّده مسؤول المخيم، ويتحقق فيه رب الأسرة من هويته قبل إنشاء حسابه. |
| **المساعدات** | تسجيل التوزيعات (الأنواع، الجهة المانحة، الأسر المستفيدة، التاريخ)، وسجل مساعدات للأسرة يطّلع عليه النازح، وإشعار تلقائي للأسر المستفيدة. |
| **طلبات التسجيل** | مراجعة طلبات الانضمام وقبولها أو رفضها؛ القبول ينشئ الفرد والأسرة والحساب والإشعار في معاملة واحدة. |
| **المستندات** | رفع ومعاينة وحذف عبر دوال Edge إلى Cloudinary، مع ضبط الوصول بحسب الدور والمخيم. |
| **المراسلات والإشعارات** | رسائل بين النازح وإدارة المخيم مع الردود، وإشعارات داخل التطبيق في الشريط العلوي، وتفضيلات إشعار لكل حساب. |
| **الإدارة العامة** | إدارة المخيمات ومسؤوليها، والجهات المانحة، ولوحة إحصاءات مع رسوم بيانية. |
| **التصدير** | تصدير Excel (`.xlsx`) لنتيجة الفلترة نفسها تماماً، بمولّد ملفات مدمج بلا مكتبات خارجية. |
| **تجربة الاستخدام** | واجهة عربية بالكامل، جداول تتحول إلى بطاقات على الشاشات الصغيرة، حالات تحميل وفراغ وخطأ لكل قائمة، ونوافذ تأكيد لكل عملية حذف، ودعم كامل للوحة المفاتيح. |

## الأدوار والصلاحيات

| الدور | النطاق | أبرز الصلاحيات |
|---|---|---|
| **مدير النظام** | كل المخيمات (حساب واحد فقط) | إدارة المخيمات ومسؤوليها والجهات المانحة، والاطلاع على بيانات جميع المخيمات، والإحصاءات العامة، والتصدير. |
| **مسؤول المخيم** | مخيمه فقط | إدارة النازحين والأسر والمساعدات والمستندات، ومراجعة طلبات التسجيل، وتفعيل حسابات الأسر، والمراسلات، والتصدير. |
| **النازح** | أسرته فقط | لوحته الشخصية، وملف أسرته، وسجل مساعداتها، ومستنداتها، والمراسلة مع إدارة المخيم. |

الدور والمخيم والأسرة تُقرأ من حساب المستخدم المصادَق عليه (`profiles`) وليس من أي قيمة في المتصفح. إخفاء الأزرار في الواجهة للتجربة فقط؛ **الحد الفعلي للصلاحيات تفرضه سياسات RLS في قاعدة البيانات**.

## التقنيات المستخدمة

**الواجهة**

- HTML5 و CSS3 و JavaScript (ES6 Modules) — بلا إطار عمل وبلا خطوة بناء.
- [supabase-js](https://github.com/supabase/supabase-js) كحزمة واحدة مدمجة في المستودع (`assets/vendor/supabase-js.js`).
- [Chart.js 4](https://www.chartjs.org/) يُحمَّل عند الحاجة فقط لرسم أول مخطط.
- خطوط Google: Noto Sans Arabic و JetBrains Mono.

**الخلفية**

- Supabase Auth للمصادقة.
- PostgreSQL مع Row Level Security، ودوال RPC ومشغّلات (Triggers) لمنطق الأعمال.
- Supabase Edge Functions (Deno):
  - `documents-upload` · `documents-access` · `documents-delete` — إدارة المستندات على Cloudinary.
  - `admin-create-camp-admin` — إنشاء حسابات مسؤولي المخيمات (لمدير النظام فقط).
  - `activate-family-account` — تفعيل حساب رب الأسرة عبر رابط التفعيل.
- Cloudinary لتخزين الملفات.

**الأدوات**

- Node.js 22+ لأدوات البذر (Seed) والاختبارات فقط.
- Playwright و PGlite للاختبارات.

## البدء السريع

### المتطلبات

- خادم ملفات ثابت (أي واحد مما يلي).
- مشروع Supabase مُعدّ (انظر [إعداد الخلفية](#إعداد-الخلفية)).
- Node.js 22 أو أحدث لتوليد ملف الإعداد وتشغيل الأدوات.

### الخطوات

```bash
# 1. إعداد متغيرات البيئة
cp .env.example .env            # أدخل SUPABASE_URL و SUPABASE_ANON_KEY (المفتاح العام)

# 2. توليد ملف إعداد المتصفح
cd supabase
npm install
npm run frontend:config         # يكتب assets/js/core/supabase-config.js
cd ..

# 3. تشغيل خادم محلي
npx serve .                     # أو: python -m http.server 3000 / Live Server في VS Code
```

> المشروع يستخدم ES Modules، لذلك **لا يعمل** بفتح الملفات مباشرة عبر `file://`.

صفحة `pages/design-system.html` تعرض جميع مكوّنات الواجهة في مكان واحد لمراجعة أي تغيير بصري.

## إعداد الخلفية

### متغيرات البيئة

| المتغير | الاستخدام | آمن في المتصفح؟ |
|---|---|---|
| `SUPABASE_URL` | الواجهة والأدوات | نعم |
| `SUPABASE_ANON_KEY` | المفتاح العام (`sb_publishable_…`) للواجهة والأدوات | نعم — سياسات RLS هي التي تحمي البيانات |
| `SUPABASE_SECRET_KEY` | البذر والاختبارات فقط | **أبداً** — يتجاوز RLS بالكامل |
| `SUPABASE_DB_URL` | `supabase db push` و psql | لا — يحتوي كلمة مرور قاعدة البيانات |

### على مشروع مستضاف

```bash
cd supabase
npx supabase link --project-ref <your-project-ref>
npx supabase db push            # تطبيق المخطط
npm install
npm run seed:reset              # بيانات تطوير — يحذف كل البيانات أولاً
npm run frontend:config
```

### محلياً (يتطلب Docker)

```bash
cd supabase
npx supabase start              # يطبّق جميع الترحيلات
npm install && npm run seed:reset
```

> ⚠️ `npm run seed:reset` يحذف جميع الصفوف وحسابات المصادقة قبل البذر. **لا تشغّله أبداً على بيئة إنتاج.**

## النشر على Vercel

المشروع جاهز للنشر على Vercel عبر `vercel.json`:

1. أضف `SUPABASE_URL` و `SUPABASE_ANON_KEY` في **Environment Variables** لمشروع Vercel.
2. أمر البناء يولّد `supabase-config.js` من هذه المتغيرات، ثم يدمج ملفات CSS في `main.css` لتقليل الطلبات المعطِّلة للعرض.
3. المسار `/` يُحوَّل إلى صفحة تسجيل الدخول.

تدعم المنصة الروابط النظيفة (`displaced` بدلاً من `displaced.html`) التي تعيد كتابتها Vercel و Netlify و GitHub Pages دون فقدان معاملات الرابط.

## المعمارية

فصل الطبقات صارم ومقصود، ويُبقي الحد بين الواجهة والخلفية واضحاً تمهيداً للانتقال إلى Next.js:

```
supabase/*.js  →  core/selectors.js  →  js/pages/*  →  ui/*
الوصول للبيانات     منطق المجال          ربط الصفحة      عرض HTML
```

- **`supabase/*.js`** — الطبقة الوحيدة التي تتصل بـ Supabase عبر عميل واحد مشترك.
- **`core/selectors.js`** — دوال نقية: شروط الفلترة لكل نوع سجل، وتعريفات موحّدة (طفل، يتيم، مرضعة)، وتجميعات الإحصاءات.
- **`core/auth.js`** و **`core/router.js`** — الجلسة، وجدول الصلاحيات `can()`، وحماية المسارات وتوليد الروابط `pageUrl()`.
- **`js/pages/*`** — ربط فقط: قراءة الرابط ← جلب البيانات ← استدعاء مكوّنات العرض ← ربط الأحداث.
- **`ui/*`** — مكوّنات تعيد نصوص HTML ولا تعرف معنى البيانات. كل إدراج للبيانات يمر عبر قالب `html` الذي يهرّب القيم تلقائياً.

القوائم الكبيرة (النازحون والمساعدات والأسر) تُفلتَر وتُعدّ وتُقسَّم إلى صفحات داخل PostgreSQL، والتصدير يعيد الاستعلام نفسه فيطابق الملف ما يظهر على الشاشة تماماً.

## قواعد المجال

قواعد من العميل مطبّقة في الواجهة وقاعدة البيانات معاً. بعضها «غيابات» مقصودة وليست سهواً:

1. مدير نظام **واحد فقط**، ومسؤولو مخيمات متعددون. مسؤول المخيم هو مندوبه، ولا يوجد حقل منفصل لاسم المندوب.
2. منع التكرار يعتمد على **رقم الهوية** فقط، ولا يوجد رقم الهوية نفسه في مخيمين.
3. **لا يوجد** رقم خيمة ولا رقم كرفان ولا رقم ملف؛ يُخزَّن **نوع الخيمة** فقط (خيمة شادر / خيمة جاهزة).
4. الحقول الصحية هي **الأمراض المزمنة** و**الإعاقة** فقط.
5. القسم الاقتصادي لا يحتوي على «احتياجات الأسرة».
6. المستندات **بلا تاريخ انتهاء**، ولا يوجد نوع «إثبات نزوح».
7. البحث لا يشمل رقم الملف ولا رقم الخيمة.
8. المساعدات يضيفها ويعدّلها ويحذفها **مسؤول المخيم فقط**؛ النازح يطّلع على سجل أسرته كقائمة.
9. المساعدة **ليست معاملة مالية**: لا قيمة ولا سعر، بل ما وُزّع فعلاً (الأنواع، المانح، الأسر، المخيم، التاريخ).
10. المستفيد من المساعدة هو **الأسرة** وليس فرداً بعينه.
11. الجهة المانحة: اسم، مع هاتف **اختياري** وشخص مسؤول **اختياري** فقط.
12. الأسرة كيان مستقل برقم فريد يُولَّد في الخادم (`FAM-000001`)، وعدد أفرادها محسوب دائماً وغير مخزَّن.
13. «الطفل» هو من **دون 18 سنة** محسوباً من تاريخ الميلاد، والفئات العمرية **تراكمية** («أقل من سنتين» تشمل الرضّع دون السنة).
14. حقلا الحمل والرضاعة للإناث فقط؛ ملف الذكر يعرض «لا ينطبق».
15. التصدير إلى Excel لمدير النظام ومسؤول المخيم فقط، ويصدّر نتيجة الفلترة بدقة، ويرفض إنشاء ملف فارغ.

## الاختبارات

مجموعات الاختبار في `supabase/tests/` وتعمل بـ `node --test`، وتغطي المخطط وسياسات RLS وعزل البيانات بين المخيمات والأدوار، ومنطق الأعمال، وفحوصات متصفح حقيقية عبر Playwright.

```bash
cd supabase
npm install
npm run test:schema             # بدون اتصال: كامل الترحيلات على PGlite
npm run test:all                # المجموعة الكاملة — تتطلب .env بمفتاح السر
```

> شغّل المجموعات **واحدة تلو الأخرى** وليس بالتوازي: تسجيل الخروج عام لكل الجلسات، فتشغيلان متزامنان يُبطلان جلسات الحسابات التجريبية المشتركة.

للتغييرات البصرية: لا أخطاء في الـ Console، ولا تمرير أفقي عند 320 / 375 / 414 / 768 / 1024 / 1440 بكسل، وتحوّل الجداول إلى بطاقات دون 768 بكسل، وتجربة كاملة بلوحة المفاتيح.

## الأمان

- **المفتاح العام فقط** يصل إلى المتصفح. سكربت توليد الإعداد **يرفض** كتابة أي مفتاح سرّي (`sb_secret_…`).
- مفتاح `service_role` موجود داخل بيئة دوال Edge فقط، ولا يظهر في أي ملف تحت `assets/`.
- جميع الجداول محمية بسياسات RLS؛ نطاق المخيم والأسرة يُفرض في قاعدة البيانات بصرف النظر عن الواجهة.
- رسائل رفض التفعيل موحّدة لمنع تخمين البيانات، والرابط يُلغى تلقائياً بعد محاولات فاشلة متكررة.
- ملفات `.env` و `supabase-config.js` مستثناة من Git.
