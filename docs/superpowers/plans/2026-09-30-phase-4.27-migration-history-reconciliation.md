# Phase 4.27 — Migration History Reconciliation · Plan

Design: `docs/superpowers/specs/2026-09-30-phase-4.27-migration-history-reconciliation-design.md`.
Live project: `qlvftlecwoqmvtagaykr`. **Every live interaction below is a `SELECT`.**

## Global stop conditions

Stop and report (do not continue, do not "fix" by guessing) if any of these occurs:

- a live-only entry contains SQL whose effect cannot be explained by the live schema;
- reconciling would need a migration to be re-run against production or any DDL/DML/history write on live;
- any fingerprint kind differs from live for a reason not attributable to a platform default (§ Task 4);
- the replayed 30-file set fingerprints differently from the replayed 23-file set;
- any live row count or notification/profile state differs between the before and after snapshots;
- a test that passed at baseline fails after the change.

Rollback for the repository change: `git reset --hard HEAD` (nothing is committed before the final
verification, and nothing on live was changed, so there is nothing to undo remotely).

## Tasks

1. **Git baseline.** `git status --short`, `git branch --show-current`, `git log --oneline -10`, `git diff --stat`.
   Expect: `main`, clean, HEAD `8c763cf`. Stop if not.
2. **Read project docs.** `CLAUDE.md`, `BACKEND.md` (migration sections, §35–§38), `supabase/package.json`,
   `supabase/tests/schema.test.mjs` (replay harness). Note the filename citations in `BACKEND.md`.
3. **Inventories.**
   - Local: `supabase/migrations/*.sql` (23) — name, version, content hash (LF, normalised).
   - Live: `supabase_migrations.schema_migrations` (version, name, `statements`, md5) and `list_migrations`.
   - Output: the mapping table in the design doc §3.
4. **Schema fingerprint (read-only).** Run the same catalog query on live (`execute_sql`) and on a PGlite
   replay of the committed migrations: columns, tables/RLS flags, constraints, indexes, policies,
   functions (+ACL, secdef, `search_path`), table ACLs, triggers, views, enum types → per-kind MD5.
   Drill into any mismatching kind by per-object hash; classify each residual difference as platform
   default, rendering, comment-only or real. Stop on any "real".
5. **Classify** every discrepancy A–F (design §4). Identify probes, folded fixes, and unrecorded live
   changes (`user_preferences_update_own`, `is_orphan` ACL).
6. **Record the runtime baseline** (counts of `auth.users`, `profiles`, `families`, `family_members`,
   `aid_distributions`, `documents`, `registration_requests`, `messages`, `notifications`, `organizations`,
   `camps`, `family_activation_tokens`, migration history) and run `npm run test:all` → baseline result.
   Do not touch `supabase/migrations/` while the suite runs (it replays that directory).
7. **Stage the 8 live-only files** verbatim (from the `statements` text) outside the repo and verify each
   byte-for-byte against the live `md5`. Stop on any mismatch.
8. **Apply the repository reconciliation.**
   - `git mv` each of the 23 files to its live `version_name.sql` (mapping in design §3). No content edits.
   - Copy 7 of the 8 verified files into `supabase/migrations/`; `…081611` is excluded (not replayable on bare Postgres — found by the Task 9 replay; documented in design §6).
   - Update filename citations in `BACKEND.md`; leave dated plans/specs as historical (the design doc
     holds the old→new map).
9. **Verify the repository.**
   - Version set of `supabase/migrations/` == version set of `schema_migrations` (30 of 31 live versions present, `20260817081611` intentionally absent, none local-only).
   - Replay fingerprint of the 30-file set == replay fingerprint of the 23-file set (the pre-change one).
   - `npm run test:schema` (and `git diff -M --stat` shows the 23 renames as 100 % similarity).
10. **Verify live unchanged.** Re-run the live fingerprint and row counts; compare with Task 4/6. The
    migration history count must still be 31.
11. **Security & browser regression.** The existing suites cover RLS, role isolation, anonymous access,
    RPC grants and the anonymous family-activation flow (`phase4.*-isolation`, `phase4.17-*`,
    `rls.test.mjs`) and the Playwright flows (`phase4.23/24/25-browser`, `browser-smoke`) — run via the
    full regression; no new test architecture is added.
12. **Full regression.** `npm run test:all` → expect 0 failures, 0 skipped, exit 0. Compare with the
    Task 6 baseline.

14. **Commit.** Review `git status`/`git diff --stat`; stage only `supabase/migrations/**`, `BACKEND.md`,
