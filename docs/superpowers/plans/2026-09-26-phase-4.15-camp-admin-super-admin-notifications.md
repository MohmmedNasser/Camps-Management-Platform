# Phase 4.15 — Camp Admin & Super Admin Header Notifications — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (Native/inline execution — explicitly required for this phase; no subagent-driven development). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the last mock notification path in the shared header (`ui/layout.js`) so Camp Admin and Super Admin see real, RLS-scoped notification data in the bell badge/dropdown, exactly as Displaced already does (Phase 4.14) and `notifications.html` already does for all three roles (Phase 4.13).

**Architecture:** Collapse `resolveNotifications()`/the mark-all-read handler in `ui/layout.js` from a role-branching function to a single role-agnostic path, since live RLS inspection proved `recipient_id = auth.uid()` already governs all three roles identically. No new data-access function, no backend change.

**Tech Stack:** Vanilla ES modules, Supabase JS client, `node --test` + Playwright (existing conventions, unchanged).

**Spec:** `docs/superpowers/specs/2026-09-26-phase-4.15-camp-admin-super-admin-notifications-design.md`

## Global Constraints

- No migration, RLS policy, RPC, or Edge Function change (backend already fully supports every operation this phase needs — confirmed live, spec §3).
- No new data-access function — reuse `listNotifications`, `unreadNotificationCount`, `markAllNotificationsRead`, `mapNotificationRow` from `assets/js/supabase/notifications.js` unchanged.
- Displaced header/dashboard behavior (Phase 4.14) and `notifications.html` (Phase 4.13) must not change at all.
- Identity is always `auth.uid()` via the Supabase client session — never a URL/localStorage/DOM value.
- A second `super_admin` fixture account must never be created — `profiles_single_super_admin_idx` (unique partial index) forbids it (spec §3.5). Super Admin's mark-all-read is exercised against the real `super@camps.ps` account with capture/restore, never a fixture.
- Every write goes through RLS; no `service_role` key in any file under `assets/`.
- `dashboard.js`'s dead `notifications: select.notificationsFor(...)` field for Camp Admin/Super Admin is out of scope — do not touch `dashboard.js` in this phase.
- Arabic UI copy, markup structure, and existing header behavior (click = navigate, no click-to-mark-read, no per-item toggle) are unchanged — data source only.

## Review Focus

- **Mark-all-read must never touch another account's rows, and must never mutate seed baseline data without restoring it** — Phase 4.14 discovered its own isolation test permanently flipped `ahmad@camps.ps`'s seeded rows because the mark-all-read subtest had no capture/restore. This phase's isolation test must capture **both** the acting account's and a second account's before-state and restore the acting account's state in a `finally`, from the first draft — not as a bug fixed after the fact. Covered in Task 2.
- **No second `super_admin` fixture** — the unique partial index on `profiles(role) WHERE role = 'super_admin'` means `serviceClient.auth.admin.createUser()` + a follow-up promotion to `super_admin` would fail (or worse, if attempted destructively, could disrupt the one real super admin). The verification suite's full mark-all-read fixture cycle uses a **camp_admin** fixture only; Super Admin's mark-all-read is proven against the real account instead. Covered in Task 3.
- **Header must render on more than one page per role** — a bug that only reproduces on `dashboard.html` (e.g. a race between `mountShell()` and page-specific data loading) would be missed if every test only ever loads the dashboard. Covered in Task 3 (an additional representative page per role).
- **Empty state must be real, not fabricated** — `nour@camps.ps` (Camp Admin, active, zero seeded notifications) must render the existing empty dropdown copy with a real zero-row DB result, not a client-side placeholder. Covered in Task 3.
- **Dead-import removal must not break `dashboard.js`** — `core/selectors.js`'s `notificationsFor`/`unreadNotificationCount` stay exported and still used by `dashboard.js` via `import * as select`; only `layout.js`'s direct import of the same two names is removed. Covered in Task 1's steps (grep-verified before editing) and Task 4's regression run.

const ROOT = resolve(HERE, '../..');
const MIME = { '.html': 'text/html', '.js': 'text/javascript', '.json': 'application/json', '.css': 'text/css' };

loadDotEnv(resolve(ROOT, '.env'));

function loadDotEnv(path) {
  let contents;
  try {
    contents = readFileSync(path, 'utf8');
  } catch {
    return;
  }
  for (const line of contents.split(/\r?\n/)) {
    const match = /^\s*([A-Z0-9_]+)\s*=\s*(.*)$/.exec(line);
    if (!match) continue;
    const value = match[2].trim().replace(/^["']|["']$/g, '');
    if (!(match[1] in process.env)) process.env[match[1]] = value;
  }
}

function required(...names) {
  for (const name of names) {
    if (process.env[name]) return process.env[name];
  }
  throw new Error(`Missing ${names.join(' or ')}. Copy .env.example to .env and fill it in.`);
}

function startServer() {
  return new Promise((resolvePromise) => {
    const server = createServer(async (req, res) => {
      const safePath = normalize(decodeURIComponent(req.url.split('?')[0])).replace(/^(\.\.[/\\])+/, '');
      const candidates = extname(safePath) ? [safePath] : [safePath, `${safePath}.html`];
      for (const candidate of candidates) {
        try {
          const filePath = join(ROOT, candidate);
          const body = await readFileAsync(filePath);
          res.writeHead(200, { 'Content-Type': MIME[extname(filePath)] || 'application/octet-stream' });
          res.end(body);
          return;
        } catch {
          // try the next candidate
        }
      }
      res.writeHead(404);
      res.end('not found');
    });
    server.listen(0, '127.0.0.1', () => resolvePromise(server));
  });
}

const MIME = { '.html': 'text/html', '.js': 'text/javascript', '.json': 'application/json', '.css': 'text/css' };

loadDotEnv(resolve(ROOT, '.env'));

function loadDotEnv(path) {
  let contents;
  try {
    contents = readFileSync(path, 'utf8');
  } catch {
    return;
  }
  for (const line of contents.split(/\r?\n/)) {
    const match = /^\s*([A-Z0-9_]+)\s*=\s*(.*)$/.exec(line);
    if (!match) continue;
    const value = match[2].trim().replace(/^["']|["']$/g, '');
    if (!(match[1] in process.env)) process.env[match[1]] = value;
  }
}

function required(...names) {
  for (const name of names) {
    if (process.env[name]) return process.env[name];
  }
  throw new Error(`Missing ${names.join(' or ')}. Copy .env.example to .env and fill it in.`);
}

function startServer() {
  return new Promise((resolvePromise) => {
    const server = createServer(async (req, res) => {
      const safePath = normalize(decodeURIComponent(req.url.split('?')[0])).replace(/^(\.\.[/\\])+/, '');
      const candidates = extname(safePath) ? [safePath] : [safePath, `${safePath}.html`];
      for (const candidate of candidates) {
        try {
          const filePath = join(ROOT, candidate);
          const body = await readFileAsync(filePath);
          res.writeHead(200, { 'Content-Type': MIME[extname(filePath)] || 'application/octet-stream' });
          res.end(body);
          return;
        } catch {
          // try the next candidate
        }
      }
      res.writeHead(404);
      res.end('not found');
    });
    server.listen(0, '127.0.0.1', () => resolvePromise(server));
  });
}
