# Phase 4.8 — Documents & File Management Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **This plan is scoped for Native/inline execution only — no subagent dispatch (explicit user constraint).**

**Goal:** Connect the Camp Admin document workflow (`pages/documents.html` —
list, search, category filter, upload, preview, download, delete) to real
Supabase + Cloudinary data, fixing the currently-live upload bug the
person-picker has carried since Phase 4.1, and wiring real inline preview —
matching the pattern Phases 4.4–4.7 already established.

**Architecture:** No new backend objects — Phase 3's three Cloudinary Edge
Functions and RLS policies are reused exactly as built. This phase adds one
list function (`getCampDocuments`) to `assets/js/supabase/documents.js`, one
pure filter predicate to `core/selectors.js`, rewrites `documents.js`'s
Camp Admin branch throughout, fixes a test-cleanup gap in
`phase3-documents.test.mjs`, and does a one-time live cleanup of the debris
that gap caused.

**Tech Stack:** Vanilla ES modules, Supabase JS client, PostgREST embeds
(real FKs — no view workaround needed here), the existing Cloudinary Edge
Functions. Tests: Node's built-in `node:test` + Playwright, under
`supabase/tests/`, following the Phase 4.6/4.7 suite shape.

**Spec:** `docs/superpowers/specs/2026-09-23-phase-4.8-documents-design.md`

## Global Constraints

- Camp scope always comes from `session.campId` (never a URL/form-supplied
  camp id) — spec §7.
- No `service_role`/Cloudinary secret/database password ever appears under
  `assets/js/` — only inside `supabase/tests/*.mjs`, `supabase/seed/*.mjs`,
  and the one-off local cleanup script in Task 5 (none of which ship to the
  browser).
- `documents.html` stays open to all three roles in `PAGE_ACCESS`
  (unchanged) — only the Camp Admin branch becomes real. Super Admin and
  Displaced keep their exact current mock behavior, byte-for-byte.
- Delete always calls `cloudinary.deleteDocumentAsset(row.id)` — never
  `row.backendId` — since a `pending`-storage row has no `backendId` but
  must still be deletable (spec §2/§5).
- Upload no longer mirrors into `store.documents.create()` for the Camp
  Admin branch — the real row is the source of truth; `load()` re-fetches
  it (spec §5).
- `npm run test:all` (inside `supabase/`) must stay green after this
  phase's fix to `phase3-documents.test.mjs` and its two new suites are
  registered.
- **Deviation from the writing-plans default** (same one Phase 4.7's plan
  recorded): no committed JS unit-test runner for pure functions exists in
  this repo. Each data-access/selector task's "test" step is a manual
  Node/browser check; the real automated coverage is the two Phase 4.8
  suites built in Tasks 6–7.

## Review Focus

- **A `pending`-storage document (one of the 12 legitimate seed rows) shown
  in a real Camp Admin's list** — download/preview icons must render
  disabled (`backendId: ''`), and delete must still work (metadata-only,
  no Cloudinary call attempted). Covered in Task 1 (mapping) and Task 3
  (manual check with a seed row).
- **Uploading, then immediately deleting, the same document** — the list
  must reflect both operations via a fresh `getCampDocuments()` fetch, not
  a stale cached array. Covered in Task 3's manual check and Task 7's
  round-trip test.
- **A real image document's preview vs. a real PDF's** — only the image
  path fetches a blob and swaps in an `<img>`; the PDF path keeps the
  existing static "no preview" placeholder, never crashes trying to render
  a PDF as an image. Covered in Task 3 (manual check with one of each) and
  Task 7 item 6.
- **Two Camp Admins, cross-camp:** every existing debris row (spec §6) sits
  in one of the two real seeded camps — the isolation suite must still pass
  cleanly with that pre-existing data present, not assume a clean table.
  Covered in Task 6, written to filter by fixture-specific names rather
  than raw counts where the debris could otherwise inflate a count
  assertion.
- **The one-time debris cleanup (Task 5) must not touch the 12 legitimate
  `pending` seed rows or any row created by a fixture from Tasks 6/7** —
  Task 5 runs *before* Tasks 6/7 create anything, and its query is scoped
  to `storage_provider='cloudinary'`, which no seed row has.

```js
import { run, mapError } from './errors.js';
import { paginate, sort } from './query.js';
import { DOCUMENT_CATEGORIES } from '../core/config.js';
import { labelOf } from '../core/selectors.js';

// ... existing SORT_COLUMNS / listDocuments / getDocument / createDocumentMetadata /
//     updateDocumentMetadata / deleteDocumentMetadata stay exactly as they are ...

const DOCUMENT_SELECT =
  '*, member:family_members(full_name), family:families(reference_code), uploader:profiles!documents_uploaded_by_fkey(full_name)';

/**
 * DB row (snake_case, with the member/family/uploader embeds — all real
 * FKs, so PostgREST embeds them directly, unlike family_stats/
 * family_member_facts) -> the exact shape resultsView()/openPreview()/
 * summaryView() in documents.js already read.
 */
function mapDocumentRow(row) {
  return {
    id: row.id,
    name: row.name,
    category: row.category,
    categoryLabel: labelOf(DOCUMENT_CATEGORIES, row.category),
    categoryIcon: (DOCUMENT_CATEGORIES.find((c) => c.value === row.category) || {}).icon || 'folder',
    personName: row.member?.full_name || '—',
    familyId: row.family?.reference_code || '',
    campId: row.camp_id,
    size: row.file_size || 0,
    mime: row.mime_type || '',
    uploadedAt: row.created_at,
    uploaderName: row.uploader?.full_name || '—',
    dataUrl: '',
    // Reuses the EXISTING backendId convention used throughout documents.js:
    // a truthy value already means "this row has a Cloudinary asset,
    // addressable through the Edge Functions by this id." A pending-storage
    // row (no real asset) gets '' so the existing `row.dataUrl ||
    // row.backendId` check disables its download/preview icon unmodified.
    backendId: row.storage_provider === 'cloudinary' ? row.id : '',
  };
}

/**
 * Every document in one camp, unpaginated — the single query behind the
 * real Camp Admin list, its search/category filter and its summary stat
 * (Phase 4.8 spec §4), same convention as getCampFamilies()/
 * getCampDisplacedPersons()/getCampAidDistributions()/
 * getCampRegistrationRequests(). RLS (documents_select_scoped)
 * independently scopes every row to the caller's own camp regardless of
 * the campId argument.
 */
export async function getCampDocuments(campId) {
  const client = requireClient();
  const rows = await run(
    client.from('documents').select(DOCUMENT_SELECT).eq('camp_id', campId).order('created_at', { ascending: false })
  );
  return rows.map(mapDocumentRow);
}
```

- [ ] **Step 1: Add the predicate next to the existing document selectors**

Add immediately after the existing `documentsByCategory()` (around line

section):

```js
/**
 * Pure predicate over one real (already camelCase) document row,
 * independent of the mock searchDocuments() above — same split
 * matchesAidFilters()/matchesRegistrationRequestFilters() use for their
 * real Camp Admin pages (Phase 4.6/4.7).
 */
export function matchesDocumentFilters(row, { query = '', category = '' } = {}) {
  if (category && row.category !== category) return false;
  const term = query.trim().toLowerCase();
  if (!term) return true;
  return (
    row.name.toLowerCase().includes(term) ||
    row.personName.toLowerCase().includes(term) ||
    (row.familyId || '').toLowerCase().includes(term)
  );
}
```

```js
async function destroyCloudinaryAsset(publicId, resourceType = 'image') {
  // Same signed-destroy request shape as supabase/functions/_shared/cloudinary.ts,
  // called directly here since this test runs in Node, not Deno.
  const cloudName = required('CLOUDINARY_CLOUD_NAME');
  const apiKey = required('CLOUDINARY_API_KEY');
  const apiSecret = required('CLOUDINARY_API_SECRET');
  const timestamp = Math.floor(Date.now() / 1000);
  const toSign = `public_id=${publicId}&timestamp=${timestamp}${apiSecret}`;
  const signature = createHash('sha1').update(toSign).digest('hex');
  const body = new URLSearchParams({ public_id: publicId, api_key: apiKey, timestamp: String(timestamp), signature });
  await fetch(`https://api.cloudinary.com/v1_1/${cloudName}/${resourceType}/destroy`, { method: 'POST', body });
}
```
