# Phase 4.10 — Camps & Camp Admins on Real Data — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Subagent-driven development is explicitly prohibited for this plan by the project owner** — implement inline, in this session, task by task.

**Goal:** Connect `camps.html` and `camp-admins.html` (both Super-Admin-only) to real Supabase data, going fully real with no mock branch — the same end-state Phase 4.9 reached for `organizations.html`.

**Architecture:** Thin data-access additions in `assets/js/supabase/camps.js` and `profiles.js` (reusing `statistics.js`/`profiles.js` composition already proven in `dashboard.js`), one new pure filter in `core/selectors.js`, one small `ui/record-forms.js` change, then swap the two page modules' data source from `core/store.js`/`core/selectors.js` mock reads to the real functions — same shape every Phase 4.2–4.9 page swap already used. One new database function (`get_camp_admin_accounts`, `SECURITY DEFINER`, internally checks `is_super_admin()`) is the only schema change, needed solely because `profiles` has no `email` column. Camp-admin **creation** is explicitly deferred (see design doc §1.3/§4) — not implemented, not faked.

**Tech Stack:** Vanilla ES modules, Supabase (Postgres + RLS + PostgREST + Auth), Node `--test` + Playwright for verification (matches `supabase/tests/phase4.9-*.test.mjs`).

**Spec:** `docs/superpowers/specs/2026-08-19-phase-4.10-camps-camp-admins-design.md`

## Global Constraints

- Both pages are Super-Admin-only in `PAGE_ACCESS` — no second role branch to build or preserve.
- No `service_role` key, DB password, or Cloudinary secret in any browser-reachable file.
- No new RLS policy, no new table, no new enum — the one new object is a `SECURITY DEFINER` function that re-checks `is_super_admin()` internally.
- Camp-admin account **creation** is deferred — do not implement `auth.signUp()`-based creation from the Super Admin's session under any circumstance (session-hijack risk, documented in the design doc).
- Every new data-access function follows existing file conventions exactly: `requireClient()`, `run()`/`mapError()` from `errors.js`, camelCase-in/out at the JS boundary, snake_case at the SQL boundary.
- `npm run test:all` (from `supabase/`) must pass before and after, unmodified suites untouched.
- Do not touch `core/auth.js` PERMISSIONS, `core/router.js`, or `core/config.js` PAGE_ACCESS/NAVIGATION — all already correct for this phase.

## Review Focus

1. Editing a camp admin's `camp_id` with `assignCampAdmin` while their role is already `camp_admin` must be a safe no-op re-set, not a rejected "no-change" write — confirm live, not just by reading the trigger source.
2. Deleting a camp with zero families/displaced/admins (per `listCampsWithStats()`) but a `documents` or `registration_requests` row still attached must still surface the friendly "camp in use" message via the DB-RESTRICT catch path, not a raw error.
3. The edit form's disabled email field must not block form submission or silently drop from `readForm()` — verify with an actual save, not a markup read.
4. `toolbar.js`'s `getFilters()` is called synchronously by `initToolbar` (confirmed: `openFilterSheet({ filters: getFilters(), ... })`, not awaited) — `listCampOptions()` must be fetched once and cached in `state`, never passed as an async `getFilters` source.
5. A `camp_admin` session hitting `camps.html`/`camp-admins.html` directly by URL must redirect to `404.html` — test this role explicitly, not just `displaced`.

**Files:**

**Interfaces:**

- [ ] **Step 1: Write the migration file**

```sql
-- supabase/migrations/20260819000000_phase4_10_camp_admin_accounts.sql
-- Phase 4.10: exposes camp-admin accounts with their auth email to
-- super_admin only. profiles has no email column (auth.users is not
-- reachable via the publishable key), so this is the one safe,
-- SECURITY DEFINER read needed to list camp admins for real.

create or replace function public.get_camp_admin_accounts()
returns table (
  id uuid,
  full_name text,
  email text,
  phone text,
  camp_id uuid,
  camp_name text,
  status public.account_status,
  created_at timestamptz
)
language plpgsql
security definer
set search_path to ''
as $$
begin
  if not private.is_super_admin() then
    raise exception 'لا تملك صلاحية عرض حسابات مسؤولي المخيمات' using errcode = '42501';
  end if;

  return query
  select p.id, p.full_name, u.email, p.phone, p.camp_id, c.name, p.status, p.created_at
  from public.profiles p
  join auth.users u on u.id = p.id
  left join public.camps c on c.id = p.camp_id
  where p.role = 'camp_admin'
  order by p.created_at;
end;
$$;

revoke all on function public.get_camp_admin_accounts() from public;
grant execute on function public.get_camp_admin_accounts() to authenticated;
```

```js
import { getDashboardStatistics } from './statistics.js';
import { listProfiles } from './profiles.js';
import { DataAccessError, ErrorType } from './errors.js';

/**
 * Per-camp breakdown for camps.html and camp-admins.html's summary —
 * moved here from dashboard.js's private buildCampBreakdown() (Phase 4.2)
 * so both pages share one implementation instead of two.

export async function listCampsWithStats({ status } = {}) {
  const camps = await listCamps({ status });
  return Promise.all(
    camps.map(async (camp) => {
      const [stats, admins] = await Promise.all([
        getDashboardStatistics(camp.id),
        listProfiles({ role: 'camp_admin', campId: camp.id, pageSize: 1 }),
      ]);
      return {
        id: camp.id,
        name: camp.name,
        city: camp.city,
        governorate: camp.governorate,
        status: camp.status,
        createdAt: camp.created_at,
        displacedCount: Number(stats?.total_members) || 0,
        familiesCount: Number(stats?.total_families) || 0,
        aidCount: Number(stats?.aid_distributions) || 0,
        adminsCount: admins.total,
        disabilityCount: Number(stats?.disability) || 0,
        childrenCount: Number(stats?.children_under_18) || 0,
        orphansCount: Number(stats?.orphans) || 0,
      };
    })
  );
}
```

- [ ] **Step 1: Add the function next to `matchesOrganizationFilters`/`matchesDocumentFilters`**

```js
/** Real camp-admin list filter — same split as matchesOrganizationFilters()/
 * matchesDocumentFilters()/matchesRegistrationRequestFilters()/matchesAidFilters(). */
export function matchesCampAdminFilters(row, { query = '', campId = '', status = '' } = {}) {
  if (campId && row.campId !== campId) return false;
  if (status && row.status !== status) return false;
  const term = query.trim().toLowerCase();
  if (!term) return true;
  return (
    row.fullName.toLowerCase().includes(term) ||
    row.email.toLowerCase().includes(term) ||
    (row.phone || '').includes(term)
  );
}
```
