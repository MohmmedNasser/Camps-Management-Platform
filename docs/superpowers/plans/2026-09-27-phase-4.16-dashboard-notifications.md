# Phase 4.16 — Dashboard Notification Stats Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (Native/inline execution — explicitly chosen; do NOT use superpowers:subagent-driven-development). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Camp Admin and Super Admin dashboards a real, rendered unread-notification stat card (matching the Displaced dashboard's existing one), replacing the dead mock `notifications` field `dashboard.js`'s `collect()` currently computes for those two roles — with dedicated isolation/verification tests, docs, and a green `npm run test:all`.

**Architecture:** Move notification fetching into `getSuperAdminDashboard()`/`getCampAdminDashboard()` (`assets/js/supabase/dashboard.js`), reusing the already-proven `unreadNotificationCount()` (`assets/js/supabase/notifications.js`, RLS-scoped to `auth.uid()`), exactly as `getDisplacedDashboard()` already does. Render it as one new `statCard` per view, copied from the Displaced view's existing card.

**Tech Stack:** Vanilla ES modules, Supabase JS client, `node:test` + Playwright (`supabase/tests/*.mjs`), live Supabase project `qlvftlecwoqmvtagaykr`.

**Spec:** `docs/superpowers/specs/2026-09-27-phase-4.16-dashboard-notifications-design.md`

## Global Constraints

- No `service_role` in any file under `assets/`. (Spec §6)
- No client-provided recipient id anywhere in the notification-count call chain — identity is `auth.uid()` only. (Spec §6)
- No new RPC, Edge Function, migration, or RLS change. (Spec §9)
- No changes to `ui/layout.js`, `notifications.html`, `PAGE_ACCESS`, or `NAVIGATION`. (Spec §9)
- Displaced dashboard behavior (`getDisplacedDashboard`, `displacedView`'s existing stat card) must not change shape or regress. (Spec §4.2)
- Test fixtures: no second `super_admin` account can ever be created (`profiles_single_super_admin_idx` unique partial index) — Super Admin write-path tests must use the real `super@camps.ps` account with capture/restore, never a fixture. (Spec §7, precedent: Phase 4.15)
- Any test-created data or read-state mutation must be restored in a `finally` block before the suite exits.
- Nothing gets pushed to `origin`.

## Review Focus

- **Duplicate-request behavior** — the header (`mountShell`) and the dashboard now both call `unreadNotificationCount()` independently for Camp Admin/Super Admin (already true for Displaced since 4.14). A reasonable person would expect the two numbers never to visibly disagree on one page load. → Task 6's verification test asserts header badge value == dashboard stat card value == independent DB count, same page load, all three roles.
- **Zero-unread rendering** — `nour@camps.ps` (real Camp Admin, 0 notifications) must render the stat card with `0`, not hide the card, not show a blank/undefined value, and not throw. → Task 6.
- **Grid layout with an odd card count** — Camp Admin goes 8→9 cards, Super Admin 10→11, inside a `.grid--4` that wraps. A reasonable person would expect no horizontal overflow at any breakpoint after the count changes. → Task 6's responsive subtest (320/375/768/1024/1280/1440).
- **Cross-role/cross-account leakage via the dashboard specifically** (not just the header, already covered by Phase 4.15) — a reasonable person would expect a Camp Admin's dashboard to never be able to show another account's count via a spoofed query param, localStorage value, or any other client-controlled input. → Task 5's isolation test.
- **Mark-all-read reflected on the dashboard, not just the header** — Phase 4.14/4.15 proved the header updates after mark-all-read; this phase adds a second on-page consumer of the same count (the stat card) that must also update. A reasonable person would expect both surfaces to move together, not just one. → Task 6's fixture mark-all-read subtest checks the dashboard stat card value, not only the header badge.

const HERE = dirname(fileURLToPath(import.meta.url));
const ROOT = resolve(HERE, '../..');
const MIME = { '.html': 'text/html', '.js': 'text/javascript', '.json': 'application/json', '.css': 'text/css' };

loadDotEnv(resolve(ROOT, '.env'));

function loadDotEnv(path) {
  let contents;
  try {
    contents = readFileSync(path, 'utf8');
  } catch {
    return;
  }
  for (const line of contents.split(/\r?\n/)) {
    const match = /^\s*([A-Z0-9_]+)\s*=\s*(.*)$/.exec(line);
    if (!match) continue;
    const value = match[2].trim().replace(/^["']|["']$/g, '');
    if (!(match[1] in process.env)) process.env[match[1]] = value;
  }
}

function required(...names) {
  for (const name of names) {
    if (process.env[name]) return process.env[name];
  }
  throw new Error(`Missing ${names.join(' or ')}. Copy .env.example to .env and fill it in.`);
}

function startServer() {
  return new Promise((resolvePromise) => {
    const server = createServer(async (req, res) => {
      const safePath = normalize(decodeURIComponent(req.url.split('?')[0])).replace(/^(\.\.[/\\])+/, '');
      const candidates = extname(safePath) ? [safePath] : [safePath, `${safePath}.html`];
      for (const candidate of candidates) {
        try {
          const filePath = join(ROOT, candidate);
          const body = await readFileAsync(filePath);
          res.writeHead(200, { 'Content-Type': MIME[extname(filePath)] || 'application/octet-stream' });
          res.end(body);
          return;
        } catch {
          // try the next candidate
        }
      }
      res.writeHead(404);
      res.end('not found');
    });
    server.listen(0, '127.0.0.1', () => resolvePromise(server));
  });
}

function loadDotEnv(path) {
  let contents;
  try {
    contents = readFileSync(path, 'utf8');
  } catch {
    return;
  }
  for (const line of contents.split(/\r?\n/)) {
    const match = /^\s*([A-Z0-9_]+)\s*=\s*(.*)$/.exec(line);
    if (!match) continue;
    const value = match[2].trim().replace(/^["']|["']$/g, '');
    if (!(match[1] in process.env)) process.env[match[1]] = value;
  }
}

function required(...names) {
  for (const name of names) {
    if (process.env[name]) return process.env[name];
  }
  throw new Error(`Missing ${names.join(' or ')}. Copy .env.example to .env and fill it in.`);
}

function startServer() {
  return new Promise((resolvePromise) => {
    const server = createServer(async (req, res) => {
      const safePath = normalize(decodeURIComponent(req.url.split('?')[0])).replace(/^(\.\.[/\\])+/, '');
      const candidates = extname(safePath) ? [safePath] : [safePath, `${safePath}.html`];
      for (const candidate of candidates) {
        try {
          const filePath = join(ROOT, candidate);
          const body = await readFileAsync(filePath);
          res.writeHead(200, { 'Content-Type': MIME[extname(filePath)] || 'application/octet-stream' });
          res.end(body);
          return;
        } catch {
          // try the next candidate
        }
      }
      res.writeHead(404);
      res.end('not found');
    });
    server.listen(0, '127.0.0.1', () => resolvePromise(server));
  });
}
